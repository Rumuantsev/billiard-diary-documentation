# Описание аналитики

Документ описывает целевую страницу аналитики тренера и ее соответствие текущему backend. Описание опирается на прототип `front-prototypes/withGroups/coach/analytics.html` и на реализованный read-only модуль `/analytics`.

Аналитика в MVP не является рекомендательной системой. Это набор расчетных показателей, графиков и таблиц, которые помогают тренеру увидеть посещаемость спортсменов, объем выполненной работы, результативность и динамику прогресса по упражнениям.

## 1. Назначение страницы

Страница аналитики предназначена для тренера и отвечает на три практических вопроса:

- кто посещает тренировки стабильно, а кто находится в зоне внимания;
- сколько упражнений спортсмены успевают выполнить за тренировку и с какой точностью;
- растет ли конкретный спортсмен в конкретном упражнении.

На странице есть три раздела:

- **Посещаемость**;
- **Результативность**;
- **Прогресс по упражнениям**.

Backend отдает для этих разделов готовые агрегаты, а не сырые данные тренировок:

```text
GET /analytics/filters
GET /analytics/attendance
GET /analytics/performance
GET /analytics/progress
```

Все endpoints аналитики доступны только пользователю с ролью `coach`.

## 2. Общая логика фильтров

### 2.1. Период

В прототипе тренер выбирает период одним из способов:

- текущий месяц;
- прошлый месяц;
- текущий год;
- последние 90 дней;
- произвольный период.

Frontend преобразует выбранный вариант в параметры backend:

```text
dateFrom
dateTo
```

Backend проверяет, что даты валидные и что `dateFrom` не позже `dateTo`. В расчет попадают записи, у которых `athlete_training.starts_at` находится внутри выбранного периода.

### 2.2. Единое бизнес-правило среза

Для всех разделов аналитики действует единое правило:

| Выбор фильтров                 | Что считается                                                                              |
| ------------------------------ | ------------------------------------------------------------------------------------------ |
| Группа не выбрана              | Аналитика по всей школе текущего тренера.                                                  |
| Выбрана группа                 | Аналитика только по выбранной группе.                                                      |
| Выбран спортсмен               | Аналитика только по выбранному спортсмену. Спортсмен должен принадлежать выбранной группе. |
| Выбраны спортсмен и упражнение | Аналитика только по выбранной паре спортсмен + упражнение.                                 |

Backend-ограничение: `athleteId` можно передавать только вместе с `groupId`. Если `athleteId` передан без `groupId`, backend возвращает ошибку `analytics_group_required`.

### 2.3. Фильтр спортсменов

Список спортсменов строится через `GET /analytics/filters`.

| Ситуация             | Что возвращает backend                                                    |
| -------------------- | ------------------------------------------------------------------------- |
| `groupId` не передан | `athletes` возвращается пустым списком.                                   |
| `groupId` передан    | `athletes` содержит только спортсменов выбранной группы текущего тренера. |

Это соответствует прототипу: пока группа не выбрана, список спортсменов пустой или заблокирован.

### 2.4. Фильтр упражнений

Список упражнений также строится через `GET /analytics/filters`.

| Ситуация              | Что возвращает backend                                                          |
| --------------------- | ------------------------------------------------------------------------------- |
| `athleteId` не выбран | Все активные упражнения текущего тренера.                                       |
| `athleteId` выбран    | Только упражнения, которые этот спортсмен реально выполнял в выбранном периоде. |

Фильтр `exerciseId` используется в разделах `Результативность` и `Прогресс по упражнениям`. В разделе `Посещаемость` упражнения не участвуют.

## 3. Источники данных

Аналитика рассчитывается поверх текущей модели тренировок.

| Данные                 | Таблица / поля                       | Назначение                                                 |
| ---------------------- | ------------------------------------ | ---------------------------------------------------------- |
| Группы                 | `groups`                             | Фильтр группы и название группы в таблицах.                |
| Спортсмены             | `users`, `athlete_groups`            | Фильтр спортсмена и группировка по спортсменам.            |
| Групповые тренировки   | `group_training`                     | Связь персональных тренировок с группой.                   |
| Тренировки спортсменов | `athlete_training`                   | Основная единица посещаемости и дата аналитики.            |
| Посещаемость           | `athlete_training.attendance_status` | Источник истины для посещаемости.                          |
| Элементы тренировки    | `training_item`                      | Назначенные упражнения, попытки, успешные попытки, статус. |
| Упражнения             | `exercise`                           | Название упражнения и фильтр упражнения.                   |

Отдельной таблицы `attendance` в актуальной backend-логике нет. Посещаемость считается по `athlete_training.attendance_status`.

## 4. Раздел "Посещаемость"

### 4.1. Endpoint

```text
GET /analytics/attendance
```

Query parameters:

```text
dateFrom
dateTo
groupId
athleteId
```

`exerciseId` не используется и не принимается этим endpoint.

### 4.2. Что отображается

Раздел показывает:

- количество посещений;
- количество пропусков;
- среднюю посещаемость;
- зону внимания;
- график посещаемости по датам;
- сравнение спортсменов по посещаемости;
- таблицу детализации по тренировкам или по спортсменам.

### 4.3. KPI посещаемости

Backend возвращает:

```text
attendance.kpi.presentCount
attendance.kpi.missedCount
attendance.kpi.attendanceRate
attendance.kpi.riskAthletes
```

| Показатель       | Расчет                                                                                             |
| ---------------- | -------------------------------------------------------------------------------------------------- |
| `presentCount`   | Количество `athlete_training` со статусом посещения `present`.                                     |
| `missedCount`    | Количество `athlete_training` со статусом посещения `absent`.                                      |
| `attendanceRate` | `presentCount / (presentCount + missedCount) * 100`.                                               |
| `riskAthletes`   | До 5 спортсменов с посещаемостью `<= 70%`, если у спортсмена есть минимум 2 отмеченные тренировки. |

Статус `unknown` означает, что посещение еще не отмечено. Такие записи не участвуют в расчетах посещаемости.

`athlete_training.status = missed` считается legacy/техническим статусом и не является источником истины для посещаемости.

### 4.4. График по датам

Backend возвращает:

```text
attendance.byDate[]
```

Каждая строка содержит:

```text
date
presentCount
missedCount
attendanceRate
```

В прототипе это отображается как столбчатый график с двумя значениями по каждой дате: был / не пришел.

### 4.5. Таблица по тренировкам

Backend возвращает:

```text
attendance.byTraining[]
```

Каждая строка соответствует групповой тренировке или индивидуальной тренировке спортсмена:

```text
groupTrainingId
athleteTrainingId
date
groupId
groupName
presentCount
missedCount
attendanceRate
```

Если запись относится к групповой тренировке, заполнен `groupTrainingId`. Если это индивидуальная тренировка без группы, заполнен `athleteTrainingId`.

Этот режим отвечает на вопрос: как прошла конкретная тренировка по посещаемости.

### 4.6. Таблица по спортсменам

Backend возвращает:

```text
attendance.byAthlete[]
```

Каждая строка содержит:

```text
athleteId
athleteName
groupId
groupName
presentCount
missedCount
attendanceRate
lastTrainingAt
```

Этот режим отвечает на вопрос: какие спортсмены посещают занятия стабильно, а какие требуют внимания.

### 4.7. Поведение фильтров

| Фильтр            | Поведение                                                                          |
| ----------------- | ---------------------------------------------------------------------------------- |
| Группа не выбрана | Посещаемость считается по всей школе тренера.                                      |
| Группа выбрана    | Посещаемость считается только по персональным тренировкам спортсменов этой группы. |
| Спортсмен выбран  | KPI, графики и таблицы сужаются до выбранного спортсмена.                          |

Упражнения в посещаемости не учитываются.

## 5. Раздел "Результативность"

### 5.1. Endpoint

```text
GET /analytics/performance
```

Query parameters:

```text
dateFrom
dateTo
groupId
athleteId
exerciseId
```

### 5.2. Что отображается

Раздел показывает:

- общую точность;
- количество назначенных упражнений;
- количество выполненных упражнений;
- общее количество попыток;
- график точности по датам;
- график объема работы по датам;
- таблицу в сводном или детальном режиме.

Бизнес-смысл раздела: оценить общий объем и результативность работы за период. Это срез того, сколько и насколько успешно было выполнено, а не долгосрочный анализ навыка.

### 5.3. KPI результативности

Backend возвращает:

```text
performance.kpi.accuracy
performance.kpi.assignedItemsCount
performance.kpi.completedItemsCount
performance.kpi.totalAttempts
```

| Показатель            | Расчет                                                                              |
| --------------------- | ----------------------------------------------------------------------------------- |
| `accuracy`            | `totalSuccesses / totalAttempts * 100`, только по завершенным элементам тренировки. |
| `assignedItemsCount`  | Количество активных `training_item` в выбранном срезе.                              |
| `completedItemsCount` | Количество `training_item` со статусом `completed`.                                 |
| `totalAttempts`       | Сумма `result_attempts` по завершенным элементам тренировки.                        |

Если попыток нет, точность считается равной `0%`.

### 5.4. График точности по датам

Backend возвращает:

```text
performance.accuracyByDate[]
```

Поля:

```text
date
attempts
successes
accuracy
```

В расчет попадают только элементы тренировки со статусом `completed`.

### 5.5. График объема работы

Backend возвращает:

```text
performance.volumeByDate[]
```

Поля:

```text
date
assigned
completed
```

В прототипе график объема сравнивает только `assigned` и `completed`. Попытки не добавляются в этот график, потому что имеют другой масштаб и визуально ломают сравнение количества упражнений.

### 5.6. Таблица результативности

Backend возвращает:

```text
performance.table.mode
performance.table.rows[]
```

Режим таблицы зависит от фильтров:

| Условие                               | `mode`    | Смысл                                              |
| ------------------------------------- | --------- | -------------------------------------------------- |
| Не выбран ни спортсмен, ни упражнение | `summary` | Одна строка на персональную тренировку спортсмена. |
| Выбран спортсмен или упражнение       | `detail`  | Одна строка на конкретный элемент тренировки.      |

#### Summary mode

Строка содержит:

```text
athleteTrainingId
groupTrainingId
date
athleteId
athleteName
groupId
groupName
attendanceStatus
assignedItemsCount
completedItemsCount
totalAttempts
totalSuccesses
accuracy
```

Этот режим удобен для ответа: сколько упражнений спортсмен успел выполнить за тренировку и с какой точностью.

#### Detail mode

Строка содержит:

```text
date
athleteTrainingId
groupTrainingId
athleteId
athleteName
groupId
groupName
exerciseId
exerciseTitle
targetAttempts
resultAttempts
resultSuccesses
status
accuracy
```

Этот режим удобен, когда тренер уже выбрал спортсмена или упражнение и хочет посмотреть конкретные выполнения.

## 6. Раздел "Прогресс по упражнениям"

### 6.1. Endpoint

```text
GET /analytics/progress
```

Query parameters:

```text
dateFrom
dateTo
groupId
athleteId
exerciseId
```

### 6.2. Что отображается

Раздел показывает динамику по парам:

```text
спортсмен + упражнение
```

Это принципиально отличается от раздела `Результативность`:

- `Результативность` отвечает: сколько работы сделано и с какой точностью за период;
- `Прогресс по упражнениям` отвечает: растет ли конкретный спортсмен в конкретном упражнении.

### 6.3. KPI прогресса

Backend возвращает:

```text
progress.pairsCount
progress.growthCount
progress.declineCount
progress.stableCount
```

| Показатель     | Что означает                                     |
| -------------- | ------------------------------------------------ |
| `pairsCount`   | Количество найденных пар спортсмен + упражнение. |
| `growthCount`  | Количество пар с трендом `growth`.               |
| `declineCount` | Количество пар с трендом `decline`.              |
| `stableCount`  | Количество пар с трендом `stable`.               |

### 6.4. Правила расчета пары

В расчет попадают только элементы тренировки:

- `training_item.deleted_at IS NULL`;
- `training_item.status = completed`;
- `result_attempts > 0`.

Для каждой пары `athleteId + exerciseId` backend сортирует выполнения по дате и id элемента тренировки.

Расчет:

```text
executions = количество завершенных выполнений пары
attempts = сумма result_attempts
avgAccuracy = сумма result_successes / сумма result_attempts * 100
firstAvg = средняя точность первых до 3 выполнений
lastAvg = средняя точность последних до 3 выполнений
delta = lastAvg - firstAvg
```

### 6.5. Тренд

Backend использует следующие правила:

| Условие            | Тренд     |
| ------------------ | --------- |
| `delta >= 7` п.п.  | `growth`  |
| `delta <= -7` п.п. | `decline` |
| Остальные значения | `stable`  |

### 6.6. График прогресса

Backend возвращает:

```text
progress.chartSeries[]
```

В `chartSeries` попадают первые 8 строк после сортировки по значимости изменения. Каждая серия содержит:

```text
athleteId
athleteName
exerciseId
exerciseTitle
trend
points[]
```

`points[]` содержит дату и точность выполнения. В прототипе это отображается как линейный график по выбранным парам спортсмен + упражнение.

### 6.7. Таблица прогресса

Backend возвращает:

```text
progress.rows[]
```

Строка содержит:

```text
athleteId
athleteName
groupId
groupName
exerciseId
exerciseTitle
executions
attempts
avgAccuracy
firstAvg
lastAvg
delta
trend
```

Таблица отвечает на вопрос: какой спортсмен в каком упражнении растет, снижается или остается без явного изменения.

## 7. Права доступа и валидация

### 7.1. Роль

Все endpoints `/analytics/*` доступны только тренеру. Если пользователь не является тренером, backend возвращает `403 forbidden`.

### 7.2. Группа

`groupId` должен принадлежать текущему тренеру. Если группа не найдена среди групп тренера, backend возвращает `404 not_found`.

### 7.3. Спортсмен

`athleteId` можно использовать только вместе с `groupId`. Спортсмен должен:

- принадлежать текущему тренеру;
- входить в выбранную группу.

Иначе backend возвращает бизнес-ошибку.

### 7.4. Упражнение

`exerciseId` должен принадлежать текущему тренеру. Если упражнение не найдено среди упражнений тренера, backend возвращает `404 not_found`.

На текущем backend публичная библиотека упражнений не участвует в analytics API: упражнения берутся из активных упражнений автора-тренера.

## 8. Соответствие endpoint и разделов страницы

| Раздел страницы         | Endpoint                     | Основной объект ответа |
| ----------------------- | ---------------------------- | ---------------------- |
| Фильтры                 | `GET /analytics/filters`     | `filters`              |
| Посещаемость            | `GET /analytics/attendance`  | `attendance`           |
| Результативность        | `GET /analytics/performance` | `performance`          |
| Прогресс по упражнениям | `GET /analytics/progress`    | `progress`             |

## 9. Соответствие полям модели данных

| Показатель                      | Основные поля                              |
| ------------------------------- | ------------------------------------------ |
| Период аналитики                | `athlete_training.starts_at`               |
| Группа                          | `group_training.group_id`, `groups.id`     |
| Спортсмен                       | `athlete_training.athlete_id`, `users.id`  |
| Посещаемость                    | `athlete_training.attendance_status`       |
| Упражнение                      | `training_item.exercise_id`, `exercise.id` |
| План попыток                    | `training_item.target_attempts`            |
| Попытки                         | `training_item.result_attempts`            |
| Успешные попытки                | `training_item.result_successes`           |
| Статус элемента тренировки      | `training_item.status`                     |
| Исключение удаленных элементов  | `training_item.deleted_at IS NULL`         |
| Исключение удаленных тренировок | `athlete_training.deleted_at IS NULL`      |

## 10. Важные ограничения MVP

- Аналитика является read-only модулем и не изменяет данные.
- `unknown` посещаемость не считается ни посещением, ни пропуском.
- Если тренер отмечает `attendanceStatus = absent`, активные элементы этой тренировки soft-delete'ятся и перестают участвовать в результативности и прогрессе.
- Если затем вернуть посещаемость в `present` или `unknown`, backend восстанавливает только элементы, удаленные именно действием посещаемости.
- История тренировок использует текущее состояние упражнения из таблицы `exercise`; отдельного snapshot упражнения в `training_item` нет.
- Автоматической рекомендательной системы нет: выводы строятся только простыми расчетами и сортировками.
