# Нефункциональные требования

Нефункциональные требования описывают проверяемые характеристики качества системы: доступность, производительность, безопасность, защиту данных, совместимость, эксплуатацию и восстановление после сбоев.

## 1. Доступность и надежность

### 1.1. Доступность системы

- **НФТ-1.1** — Система должна быть доступна пользователям круглосуточно.
- **НФТ-1.2** — Доступность системы должна составлять не менее 95% календарного времени в год.
- **НФТ-1.3** — При недоступности backend пользовательский интерфейс должен отображать сообщение об ошибке на русском языке.
- **НФТ-1.4** — Сообщение о недоступности backend должно содержать указание, что действие не выполнено и его необходимо повторить позже.

### 1.2. Сохранность данных

- **НФТ-1.5** — Данные, для которых система вернула успешный ответ о сохранении, не должны теряться при последующих сбоях приложения.
- **НФТ-1.6** — После успешного сохранения результата тренировки повторное открытие тренировки должно отображать сохраненные значения попыток и успешных попыток.
- **НФТ-1.7** — После успешного создания тренировки повторное открытие календаря или списка тренировок должно отображать созданную тренировку.

## 2. Производительность

### 2.1. Расчетная нагрузка

- **НФТ-2.1** — Система должна поддерживать работу не менее 50 тренеров.
- **НФТ-2.2** — Система должна поддерживать хранение и обработку данных не менее 100 групп.
- **НФТ-2.3** — Система должна поддерживать создание и просмотр не менее 300 групповых тренировок в неделю.
- **НФТ-2.4** — Система должна сохранять работоспособность при одновременной работе пользователей в рамках расчетной нагрузки.

### 2.2. Время ответа

- **НФТ-2.5** — Не менее 90% API-запросов должны выполняться быстрее чем за 2 секунды при расчетной нагрузке.
- **НФТ-2.6** — Запросы получения календаря тренировок должны выполняться не дольше 3 секунд при расчетной нагрузке.
- **НФТ-2.7** — Запросы получения аналитических данных должны выполняться не дольше 5 секунд при расчетной нагрузке.
- **НФТ-2.8** — Время ответа должно измеряться от момента получения backend запроса до момента отправки backend ответа.

### 2.3. Списки и пагинация

- **НФТ-2.9** — Списки пользователей должны поддерживать постраничную загрузку или ограничение размера возвращаемого набора данных.
- **НФТ-2.10** — Списки упражнений должны поддерживать постраничную загрузку или ограничение размера возвращаемого набора данных.
- **НФТ-2.11** — Списки тренировок должны поддерживать постраничную загрузку или ограничение размера возвращаемого набора данных.
- **НФТ-2.12** — Для списков тренировок система должна поддерживать фильтрацию по периоду.

## 3. Безопасность

### 3.1. Авторизация

- **НФТ-3.1** — Все защищенные действия должны требовать авторизации пользователя.
- **НФТ-3.2** — Авторизация API должна выполняться с использованием JWT.
- **НФТ-3.3** — API-запрос без действительного JWT к защищенному ресурсу должен завершаться ошибкой доступа.
- **НФТ-3.4** — Время действия JWT должно быть ограничено настройкой системы.

### 3.2. Пароли

- **НФТ-3.5** — Пароли пользователей должны храниться только в виде криптографического хеша.
- **НФТ-3.6** — Система не должна возвращать пароль или хеш пароля в ответах API.
- **НФТ-3.7** — При входе пользователя система должна сравнивать введенный пароль с сохраненным хешем.

### 3.3. Разграничение данных

- **НФТ-3.8** — Тренер не должен получать доступ к спортсменам другого тренера.
- **НФТ-3.9** — Тренер не должен получать доступ к группам другого тренера.
- **НФТ-3.10** — Тренер не должен получать доступ к упражнениям другого тренера, кроме случаев использования публичной библиотеки упражнений.
- **НФТ-3.11** — Тренер не должен изменять тренировки, созданные другим тренером.
- **НФТ-3.12** — Спортсмен не должен получать доступ к тренировкам и заданиям других спортсменов.
- **НФТ-3.13** — Спортсмен не должен получать прямой доступ к управлению упражнениями, группами и списками пользователей.
- **НФТ-3.14** — Администратор должен иметь доступ только к административным функциям, предусмотренным его ролью.

### 3.4. Валидация данных

- **НФТ-3.15** — Все входные данные API должны проверяться до выполнения бизнес-операции.
- **НФТ-3.16** — API-запрос с отсутствующим обязательным полем должен завершаться ошибкой валидации.
- **НФТ-3.17** — API-запрос с полем неподдерживаемого типа должен завершаться ошибкой валидации.
- **НФТ-3.18** — API-запрос с недопустимым значением статуса должен завершаться ошибкой валидации или ошибкой бизнес-правила.

## 4. Персональные данные

### 4.1. Состав данных

- **НФТ-4.1** — Система должна хранить персональные данные пользователей, необходимые для работы сервиса: имя и email.
- **НФТ-4.2** — Система должна хранить данные спортсмена только в объеме, необходимом для ведения тренировочного процесса.
- **НФТ-4.3** — Дополнительные данные спортсмена должны использоваться только для целей сопровождения тренировочного процесса.

### 4.2. Минимизация и удаление

- **НФТ-4.4** — Система не должна требовать от пользователя персональные данные, не используемые в пользовательских сценариях системы.
- **НФТ-4.5** — Удаление пользователей, групп, упражнений и тренировок должно выполняться как мягкое удаление.
- **НФТ-4.6** — Мягко удаленные сущности не должны отображаться в обычных рабочих списках.
- **НФТ-4.7** — Система должна сохранять связи тренировки с упражнением после мягкого удаления упражнения.

### 4.3. Журналирование действий

- **НФТ-4.8** — Система должна фиксировать в логах действия администратора по созданию и изменению пользователей.
- **НФТ-4.9** — Система должна фиксировать в логах действия тренера по созданию, изменению и мягкому удалению тренировок.
- **НФТ-4.10** — Система должна фиксировать в логах действия тренера по мягкому удалению спортсмена.
- **НФТ-4.11** — Система должна фиксировать в логах действия пользователя по изменению результата задания тренировки.

## 5. Пользовательский интерфейс

### 5.1. Адаптивность

- **НФТ-5.1** — Пользовательский интерфейс должен поддерживать ширину экрана от 360 px.
- **НФТ-5.2** — Пользовательский интерфейс должен поддерживать desktop-экраны шириной 1280 px и более.
- **НФТ-5.3** — На экранах шириной от 360 px до 767 px основные сценарии спортсмена должны быть доступны без горизонтальной прокрутки страницы.
- **НФТ-5.4** — На экранах шириной от 768 px до 1279 px основные сценарии тренера должны быть доступны без горизонтальной прокрутки страницы.
- **НФТ-5.5** — На экранах шириной 1280 px и более календарь, списки и формы тренера должны использовать доступную ширину экрана без скрытия основных элементов управления.

### 5.2. Сообщения и подтверждения

- **НФТ-5.6** — Ошибки пользовательского интерфейса должны отображаться на русском языке.
- **НФТ-5.7** — Сообщение об ошибке должно указывать действие, которое не удалось выполнить.
- **НФТ-5.8** — Перед мягким удалением спортсмена система должна запросить подтверждение.
- **НФТ-5.9** — Перед мягким удалением группы система должна запросить подтверждение.
- **НФТ-5.10** — Перед мягким удалением упражнения система должна запросить подтверждение.
- **НФТ-5.11** — Перед отменой тренировки система должна запросить подтверждение.

## 6. Совместимость

### 6.1. Браузеры

- **НФТ-6.1** — Пользовательский интерфейс должен поддерживать актуальные версии Google Chrome.
- **НФТ-6.2** — Пользовательский интерфейс должен поддерживать актуальные версии Microsoft Edge.
- **НФТ-6.3** — Пользовательский интерфейс должен поддерживать актуальные версии Safari.
- **НФТ-6.4** — Пользовательский интерфейс должен поддерживать актуальные версии Mozilla Firefox.
- **НФТ-6.5** — Поддержка браузеров Internet Explorer не требуется.

### 6.2. Часовые пояса

- **НФТ-6.6** — Пользовательский интерфейс должен отображать дату и время тренировки с учетом часового пояса пользователя.
- **НФТ-6.7** — Пользователь из другого часового пояса должен видеть время тренировки в своем локальном часовом поясе.
- **НФТ-6.8** — При создании тренировки система должна сохранять однозначный момент начала и окончания тренировки независимо от часового пояса пользователя.

## 7. Целостность данных

### 7.1. Временные ограничения

- **НФТ-7.1** — Система должна запрещать создание тренировки, у которой время начала не раньше времени окончания.
- **НФТ-7.2** — Система должна запрещать изменение тренировки, если после изменения время начала не раньше времени окончания.

### 7.2. Отображение удаленных данных

- **НФТ-7.3** — Мягко удаленные пользователи не должны отображаться в списке активных пользователей.
- **НФТ-7.4** — Мягко удаленные группы не должны отображаться в списке групп тренера.
- **НФТ-7.5** — Мягко удаленные упражнения не должны отображаться в библиотеке упражнений.
- **НФТ-7.6** — Мягко удаленные тренировки не должны отображаться в обычных списках и календаре тренировок.

### 7.3. Связность данных

- **НФТ-7.7** — Задание тренировки должно сохранять связь с упражнением после назначения.
- **НФТ-7.8** — Результат задания должен сохранять связь с заданием тренировки.
- **НФТ-7.9** — История результатов должна оставаться доступной для анализа после мягкого удаления упражнения.

## 8. Масштабируемость и изоляция организаций

### 8.1. Масштабируемость

- **НФТ-8.1** — Система должна допускать увеличение числа тренеров с 50 до 200 без изменения пользовательских сценариев.
- **НФТ-8.2** — При увеличении числа тренеров до 200 система должна сохранять авторизацию и разграничение доступа по ролям.
- **НФТ-8.3** — При увеличении числа тренеров до 200 система должна сохранять поддержку постраничной загрузки списков пользователей, упражнений и тренировок.

### 8.2. Организации

- **НФТ-8.4** — Система должна поддерживать работу нескольких школ или организаций.
- **НФТ-8.5** — Данные одной школы или организации должны быть изолированы от данных другой школы или организации.
- **НФТ-8.6** — Пользователь одной школы или организации не должен получать доступ к спортсменам, группам, тренировкам и упражнениям другой школы или организации.

## 9. Документация API

- **НФТ-9.1** — API системы должен быть описан в формате OpenAPI.
- **НФТ-9.2** — Описание OpenAPI должно содержать список доступных endpoints.
- **НФТ-9.3** — Описание OpenAPI должно содержать схемы запросов и ответов.
- **НФТ-9.4** — Описание OpenAPI должно содержать сведения о требованиях к авторизации защищенных endpoints.

## 10. Логирование и мониторинг

### 10.1. Логирование ошибок

- **НФТ-10.1** — Система должна логировать серверные ошибки.
- **НФТ-10.2** — Запись о серверной ошибке должна содержать дату и время возникновения ошибки.
- **НФТ-10.3** — Запись о серверной ошибке должна содержать технический код или описание ошибки.

### 10.2. Логирование пользовательских действий

- **НФТ-10.4** — Система должна логировать создание тренировки.
- **НФТ-10.5** — Система должна логировать изменение тренировки.
- **НФТ-10.6** — Система должна логировать изменение результата задания.
- **НФТ-10.7** — Система должна логировать мягкое удаление спортсмена.
- **НФТ-10.8** — Система должна логировать мягкое удаление тренировки.

### 10.3. Мониторинг

- **НФТ-10.9** — Система должна собирать метрику доступности API.
- **НФТ-10.10** — Система должна собирать метрику количества серверных ошибок.
- **НФТ-10.11** — Система должна собирать метрику времени ответа API.
- **НФТ-10.12** — Метрики мониторинга должны позволять проверить выполнение требований по доступности и времени ответа.

## 11. Резервное копирование и восстановление

### 11.1. Резервное копирование

- **НФТ-11.1** — База данных должна резервироваться не реже одного раза в сутки.
- **НФТ-11.2** — Резервная копия должна содержать данные пользователей, групп, упражнений, тренировок, заданий и результатов.
- **НФТ-11.3** — Система должна хранить не менее одной актуальной резервной копии базы данных.

### 11.2. Восстановление

- **НФТ-11.4** — Должна быть предусмотрена процедура восстановления базы данных из резервной копии.
- **НФТ-11.5** — После восстановления из резервной копии пользовательские данные должны быть доступны через стандартные пользовательские сценарии.
- **НФТ-11.6** — После восстановления из резервной копии система должна сохранять связи между пользователями, группами, упражнениями, тренировками, заданиями и результатами.

## 12. Локализация

- **НФТ-12.1** — Пользовательский интерфейс системы должен быть на русском языке.
- **НФТ-12.2** — Пользовательские статусы тренировок должны отображаться на русском языке.
- **НФТ-12.3** — Пользовательские статусы заданий должны отображаться на русском языке.
- **НФТ-12.4** — Сообщения об ошибках, отображаемые пользователю, должны быть на русском языке.
- **НФТ-12.5** — Даты и время должны отображаться в формате, понятном русскоязычному пользователю.
