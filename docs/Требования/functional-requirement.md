# Функциональные требования

## Приоритизация

Требования предполагают наличие приоритета в соответствии с градацией:

- **(P1)**: Без этого приложение теряет смысл.
- **(P2)**: Очень важно, но не блокирует работу.
- **(P3)**: Желательно, но можно без этого.
- **(P4)**: Не входит в текущую версию.

## 1. Авторизация и разграничение доступа

### 1.1. Доступ к системе

- **ФТ-1.1 (P1)** — Система должна предоставлять вход пользователю по учетным данным.
- **ФТ-1.2 (P1)** — При попытке перехода по прямой ссылке на защищенную страницу неавторизованным пользователем система должна перенаправлять его на страницу входа.
- **ФТ-1.3 (P1)** — При обращении к защищенному API без действующей авторизации система должна возвращать ошибку доступа.
- **ФТ-1.4 (P1)** — Система должна ограничивать доступ к функциям и данным в соответствии с ролью пользователя.

### 1.2. Роли пользователей

- **ФТ-1.5 (P1)** — Система должна поддерживать роли: администратор, тренер, спортсмен.
- **ФТ-1.6 (P1)** — Администратор должен иметь возможность управлять тренерами и упражнениями.
- **ФТ-1.7 (P1)** — Тренер должен иметь доступ к управлению своими спортсменами, группами, упражнениями, тренировками, результатами, аналитикой и комментариями.
- **ФТ-1.8 (P1)** — Спортсмен должен иметь доступ только к своим тренировкам, заданиям, результатам, истории и комментариям.
- **ФТ-1.9 (P1)** — Система должна исключать доступ спортсмена к данным других спортсменов.

## 2. Управление пользователями, спортсменами и группами

### 2.1. Администрирование пользователей

- **ФТ-2.1.1 (P1)** — Администратор должен иметь возможность создать учетную запись тренера.
- **ФТ-2.1.2 (P2)** — Администратор должен иметь возможность просматривать список пользователей.
- **ФТ-2.1.3 (P2)** — Администратор должен иметь возможность редактировать данные пользователей.

### 2.2. Создание спортсмена

- **ФТ-2.2.1 (P1)** — Тренер должен иметь возможность создать профиль спортсмена.
- **ФТ-2.2.2 (P1)** — Форма создания спортсмена должна содержать обязательные поля: имя, email и пароль.
- **ФТ-2.2.3 (P2)** — Профиль спортсмена должен поддерживать дополнительные данные: дату рождения, уровень подготовки, заметки и контактные данные.
- **ФТ-2.2.4 (P1)** — Система должна проверять обязательные поля и корректность формата данных.

### 2.3. Редактирование и мягкое удаление спортсмена

- **ФТ-2.3.1 (P3)** — Тренер должен иметь возможность редактировать профиль своего спортсмена.
- **ФТ-2.3.2 (P3)** — При редактировании профиля система должна проверять корректность изменяемых данных.
- **ФТ-2.3.3 (P4)** — Тренер должен иметь возможность выполнить мягкое удаление своего спортсмена.
- **ФТ-2.3.4 (P4)** — При мягком удалении спортсмен должен переставать отображаться в рабочих списках тренера.
- **ФТ-2.3.5 (P3)** — При мягком удалении система должна запрашивать подтверждение действия.

### 2.4. Управление группами

- **ФТ-2.4.1 (P1)** — Тренер должен иметь возможность создать группу.
- **ФТ-2.4.2 (P1)** — Название группы является обязательным полем.
- **ФТ-2.4.3 (P2)** — Описание группы является необязательным полем.
- **ФТ-2.4.4 (P1)** — Тренер должен иметь возможность добавить спортсмена в группу.
- **ФТ-2.4.5 (P1)** — Тренер должен иметь возможность удалить спортсмена из группы.
- **ФТ-2.4.6 (P2)** — Тренер должен иметь возможность просматривать карточку группы со списком спортсменов.
- **ФТ-2.4.7 (P2)** — Тренер должен иметь возможность редактировать название и описание группы.
- **ФТ-2.4.8 (P3)** — Тренер должен иметь возможность выполнить мягкое удаление группы.

## 3. Упражнения и библиотека упражнений

### 3.1. Создание упражнения

- **ФТ-3.1.1 (P1)** — Тренер должен иметь возможность создать упражнение.
- **ФТ-3.1.2 (P1)** — Форма создания упражнения должна содержать название.
- **ФТ-3.1.3 (P1)** — Форма создания упражнения должна позволять указать описание.
- **ФТ-3.1.4 (P1)** — Упражнение должно поддерживать схему расположения шаров на столе.
- **ФТ-3.1.5 (P1)** — Упражнение должно поддерживать параметры винта и силы удара.
- **ФТ-3.1.6 (P1)** — Система должна сохранять упражнение для повторного использования в тренировках.

### 3.2. Редактор позиции

- **ФТ-3.2.1 (P1)** — Пользователь должен иметь возможность добавлять шары на схему стола.
- **ФТ-3.2.2 (P1)** — Пользователь должен иметь возможность перемещать шары в пределах игрового поля.
- **ФТ-3.2.3 (P1)** — Система не должна допускать размещение шара за границами стола.
- **ФТ-3.2.4 (P1)** — Пользователь должен иметь возможность задавать линии и траектории.
- **ФТ-3.2.5 (P1)** — Пользователь должен иметь возможность настраивать винт.
- **ФТ-3.2.6 (P1)** — Пользователь должен иметь возможность задавать силу удара.
- **ФТ-3.2.7 (P1)** — Система должна сохранять схему и параметры упражнения для повторного открытия.

### 3.3. Редактирование и удаление упражнения

- **ФТ-3.3.1 (P2)** — Тренер должен иметь возможность изменять название, описание, схему позиции, винт и силу удара упражнения.
- **ФТ-3.3.2 (P2)** — Тренер должен иметь возможность выполнить мягкое удаление упражнения.
- **ФТ-3.3.3 (P2)** — При мягком удалении упражнения система должна запрашивать подтверждение.

### 3.4. Организация библиотеки упражнений

- **ФТ-3.4.1 (P2)** — Тренер должен иметь возможность создавать папки упражнений.
- **ФТ-3.4.2 (P2)** — Тренер должен иметь возможность помещать упражнение в папку.
- **ФТ-3.4.3 (P2)** — Тренер должен иметь возможность просматривать упражнения по папке.
- **ФТ-3.4.4 (P2)** — Система должна поддерживать поиск упражнений по названию.
- **ФТ-3.4.5 (P3)** — Система должна поддерживать публичную библиотеку упражнений, доступную тренерам.
- **ФТ-3.4.6 (P4)** — Тренер должен иметь возможность создать копию существующего упражнения.

## 4. Планирование тренировок

### 4.1. Создание тренировки

- **ФТ-4.1.1 (P1)** — Тренер должен иметь возможность создать тренировку для группы.
- **ФТ-4.1.2 (P1)** — При создании тренировки тренер должен выбрать группу.
- **ФТ-4.1.3 (P1)** — При создании тренировки тренер должен указать дату и время начала.
- **ФТ-4.1.4 (P1)** — При создании тренировки тренер должен указать дату и время окончания.
- **ФТ-4.1.5 (P1)** — Система должна проверять, что время начала тренировки раньше времени окончания.
- **ФТ-4.1.6 (P1)** — Тренер должен иметь возможность назначать упражнения конкретным спортсменам внутри тренировки.
- **ФТ-4.1.7 (P1)** — Набор упражнений может отличаться для разных спортсменов одной группы.
- **ФТ-4.1.8 (P1)** — Для каждого задания тренер должен иметь возможность указать плановое количество попыток.

### 4.2. Просмотр тренировок

- **ФТ-4.2.1 (P1)** — Тренер должен иметь возможность просматривать календарь тренировок.
- **ФТ-4.2.2 (P2)** — Тренер должен иметь возможность просматривать тренировки за выбранный период.
- **ФТ-4.2.3 (P2)** — Тренер должен иметь возможность фильтровать тренировки по группе, спортсмену и статусу.
- **ФТ-4.2.4 (P1)** — Спортсмен должен иметь возможность видеть назначенные ему тренировки.
- **ФТ-4.2.5 (P1)** — Спортсмен должен видеть только собственные задания внутри тренировки.

### 4.3. Редактирование тренировки

- **ФТ-4.3.1 (P2)** — Тренер должен иметь возможность редактировать дату и время запланированной тренировки.
- **ФТ-4.3.2 (P2)** — Тренер должен иметь возможность редактировать состав заданий запланированной тренировки.
- **ФТ-4.3.3 (P2)** — Тренер должен иметь возможность удалять задание из запланированной тренировки.
- **ФТ-4.3.4 (P2)** — Тренер должен иметь возможность выполнить мягкое удаление тренировки.

## 5. Статусы тренировок и заданий

### 5.1. Статусы тренировки

- **ФТ-5.1.1 (P1)** — Система должна поддерживать статусы тренировки: запланирована, выполняется, завершена, отменена, пропущена.
- **ФТ-5.1.2 (P1)** — Тренер должен иметь возможность изменить статус тренировки.
- **ФТ-5.1.3 (P1)** — Спортсмен должен иметь возможность перевести свою тренировку из статуса "запланирована" в статус "выполняется".
- **ФТ-5.1.4 (P1)** — Спортсмен должен иметь возможность перевести свою тренировку из статуса "выполняется" в статус "завершена".
- **ФТ-5.1.5 (P1)** — Система должна запрещать недопустимые переходы статусов.

### 5.2. Статусы задания тренировки

- **ФТ-5.2.1 (P1)** — Система должна поддерживать статусы задания: не начато, выполняется, завершено, пропущено.
- **ФТ-5.2.2 (P1)** — Спортсмен должен иметь возможность начать выполнение задания.
- **ФТ-5.2.3 (P1)** — Спортсмен должен иметь возможность завершить задание.
- **ФТ-5.2.4 (P1)** — Спортсмен должен иметь возможность пропустить задание.
- **ФТ-5.2.5 (P1)** — Система должна запрещать недопустимые переходы статусов задания.

## 6. Фиксация результатов

### 6.1. Ввод результатов

- **ФТ-6.1.1 (P1)** — Спортсмен должен иметь возможность указать количество выполненных попыток по заданию.
- **ФТ-6.1.2 (P1)** — Спортсмен должен иметь возможность указать количество успешных попыток по заданию.
- **ФТ-6.1.3 (P1)** — Система должна запрещать сохранение результата, в котором количество успешных попыток больше общего количества попыток.
- **ФТ-6.1.4 (P1)** — Результат задания должен сохраняться и быть доступен тренеру.

### 6.2. История выполнения

- **ФТ-6.2.1 (P1)** — Спортсмен должен иметь доступ к истории своих тренировок.
- **ФТ-6.2.2 (P1)** — Тренер должен иметь доступ к истории тренировок своих спортсменов.
- **ФТ-6.2.3 (P2)** — История тренировок должна поддерживать фильтрацию по периоду.

## 7. Посещаемость

- **ФТ-7.1 (P3)** — Система должна позволять фиксировать посещаемость спортсмена на тренировке.
- **ФТ-7.2 (P3)** — Для посещаемости должны поддерживаться значения: был, не был.
- **ФТ-7.3 (P3)** — Тренер должен иметь возможность просматривать посещаемость по группе.
- **ФТ-7.4 (P3)** — Тренер должен иметь возможность просматривать посещаемость спортсмена за выбранный период.

## 8. Аналитика

### 8.1. Общие фильтры аналитики

- **ФТ-8.1.1 (P2)** — Система должна позволять выбрать период аналитики.
- **ФТ-8.1.2 (P2)** — Система должна позволять фильтровать аналитику по группе.
- **ФТ-8.1.3 (P2)** — Система должна позволять фильтровать аналитику по спортсмену.
- **ФТ-8.1.4 (P2)** — Система должна позволять фильтровать аналитику по упражнению.

### 8.2. Аналитика посещаемости

- **ФТ-8.2.1 (P2)** — Система должна отображать количество тренировочных сессий за период.
- **ФТ-8.2.2 (P2)** — Система должна отображать среднюю посещаемость за период.
- **ФТ-8.2.3 (P2)** — Система должна отображать количество активных спортсменов за период.
- **ФТ-8.2.4 (P2)** — Система должна отображать динамику посещаемости по дням.
- **ФТ-8.2.5 (P2)** — Система должна отображать сводку посещаемости по тренировкам.

### 8.3. Аналитика результативности

- **ФТ-8.3.1 (P2)** — Система должна отображать общую точность выполнения упражнений.
- **ФТ-8.3.2 (P2)** — Система должна отображать количество назначенных заданий.
- **ФТ-8.3.3 (P2)** — Система должна отображать количество выполненных заданий.
- **ФТ-8.3.4 (P2)** — Система должна отображать динамику результативности за период.
- **ФТ-8.3.5 (P2)** — Система должна отображать детализацию результатов по спортсменам, упражнениям и датам.

### 8.4. Аналитика прогресса по упражнениям

- **ФТ-8.4.1 (P2)** — Система должна отображать среднюю точность по упражнениям.
- **ФТ-8.4.2 (P2)** — Система должна отображать количество выполнений по каждому упражнению.
- **ФТ-8.4.3 (P2)** — Система должна отображать динамику прогресса по упражнениям.

## 9. Комментарии и заметки

### 9.1. Комментарии тренера

- **ФТ-9.1.1 (P1)** — Тренер должен иметь возможность оставить комментарий к тренировке.
- **ФТ-9.1.2 (P2)** — Тренер должен иметь возможность оставить комментарий к отдельному заданию.
- **ФТ-9.1.3 (P2)** — Комментарий должен сохраняться и быть доступным для повторного просмотра.
- **ФТ-9.1.4 (P2)** — Спортсмен должен иметь возможность просматривать комментарии тренера, относящиеся к его тренировкам и заданиям.

### 9.2. Заметки спортсмена

- **ФТ-9.2.1 (P2)** — Спортсмен должен иметь возможность оставить заметку к тренировке.
- **ФТ-9.2.2 (P2)** — Спортсмен должен иметь возможность оставить заметку к заданию.
- **ФТ-9.2.3 (P2)** — Заметка спортсмена должна быть доступна тренеру.
