Функциональные требования

Приоритизация

Требования предполагают наличие приоритета в соответствии с градацией:

  • (P1): Без этого приложение теряет смысл.
  • (P2): Очень важно, но не блокирует работу.
  • (P3): Желательно, но можно без этого.
  • (P4): Не входит в текущую версию.

1. Авторизация и разграничение доступа

1.1. Доступ к системе

  • ФТ-1.2 (P1) — При попытке перехода по прямой ссылке на защищённую страницу неавторизованным пользователем система обязана перенаправить его на страницу входа.
  • ФТ-1.3 (P1) — При обращении к защищённому API без действующей авторизации система должна возвращать ошибку доступа.

1.2. Роли пользователей

  • ФТ-1.5 (P1) — Система должна поддерживать две роли: тренер и спортсмен.
  • ФТ-1.6 (P1) — Тренер должен иметь доступ к управлению спортсменами, группами, упражнениями, назначениями, аналитикой группы и комментариями.
  • ФТ-1.7 (P1) — Спортсмен должен иметь доступ только к собственным назначениям, результатам, аналитике и комментариям.
  • ФТ-1.8 (P1) — Система обязана исключать доступ спортсмена к данным других спортсменов.

2. Управление спортсменами и группами

2.1. Создание спортсмена

  • ФТ-2.1.1 (P1) — Тренер должен иметь возможность создать профиль спортсмена.
  • ФТ-2.1.2 (P1) — Форма создания спортсмена должна содержать обязательные поля:
  • Имя (минимум 2 символа, максимум 100 символов);
  • Дата рождения (корректная календарная дата).
  • ФТ-2.1.3 (P1) — Система обязана выполнять проверку обязательных полей и корректности формата данных.
  • ФТ-2.1.4 (P3) — Дополнительные поля (уровень, заметки, контактные данные) являются необязательными.

2.2. Редактирование и удаление спортсмена

  • ФТ-2.2.1 (P3) — Тренер должен иметь возможность редактировать профиль спортсмена.
  • ФТ-2.2.2 (P3) — При редактировании применяются те же ограничения, что и при создании.
  • ФТ-2.2.3 (P3) — При удалении спортсмена система должна запрашивать подтверждение действия.

2.3. Управление группами

  • ФТ-2.3.1 (P1) — Тренер должен иметь возможность создать группу.
  • ФТ-2.3.2 (P1) — Название группы является обязательным полем (3–150 символов).
  • ФТ-2.3.3 (P1) — Тренер должен иметь возможность добавлять спортсменов в группу.
  • ФТ-2.3.4 (P1) — Тренер должен иметь возможность удалять спортсменов из группы.
  • ФТ-2.3.5 (P2) — Система должна поддерживать массовое добавление и удаление спортсменов.

2.4. Посещаемость

  • ФТ-2.4.1 (P2) — Тренер должен иметь возможность фиксировать статус посещаемости спортсмена.
  • ФТ-2.4.2 (P2) — Допустимые статусы: присутствовал, отсутствовал, опоздал.
  • ФТ-2.4.3 (P2) — Система должна предоставлять просмотр истории посещаемости за выбранный период.

3. Упражнения

3.1. Создание упражнения

  • ФТ-3.1.1 (P1) — Тренер должен иметь возможность создать упражнение.
  • ФТ-3.1.2 (P1) — Форма создания упражнения должна содержать:
  • Название (3–150 символов);
  • Описание/цель (10–3000 символов);
  • Схема позиции - опционально (P2);
  • Добавление фото - опционально(P3);
  • ФТ-3.1.3 (P1) — Упражнение должно быть доступно для повторного использования.
  • ФТ-3.1.4 (P1) — Тренер должен иметь возможность создать копию существующего упражнения.

3.2. Редактирование упражнения

  • ФТ-3.2.1 (P2) — Тренер должен иметь возможность изменять название, описание и состав позиций упражнения.
  • ФТ-3.2.2 (P2) — При удалении упражнения система должна запрашивать подтверждение.
  • ФТ-3.2.3 (P2) — Удаление упражнения не должно удалять уже зафиксированные результаты его выполнения.

3.3. Организация упражнений

  • ФТ-3.3.1 (P2) — Тренер должен иметь возможность структурировать упражнения по категориям или папкам.
  • ФТ-3.3.2 (P2) — Должен быть реализован поиск по названию упражнения.
  • ФТ-3.3.3 (P2) — Результаты поиска должны отображаться немедленно после выполнения запроса.

4. Редактор позиций

Редактор позиций является отдельным модулем системы.
Позиция всегда принадлежит конкретному упражнению.

4.1. Управление шарами

  • ФТ-4.1.1 (P1) — Пользователь должен иметь возможность добавлять шары типов: solid, dashed, solidWithCoordinate.
  • ФТ-4.1.2 (P1) — Пользователь должен иметь возможность перемещать шары в пределах игрового поля.
  • ФТ-4.1.3 (P1) — Система не должна допускать размещение шара за границами стола.
  • ФТ-4.1.4 (P1) — Для шаров типа solidWithCoordinate должно отображаться расстояние до ближайшего борта.
  • ФТ-4.1.5 (P1) — Расстояние должно быть выражено в шаровых единицах и быть кратным диаметру шара.

4.2. Параметры удара

  • ФТ-4.2.1 (P1) — Для выбранного шара должна быть доступна настройка винта.
  • ФТ-4.2.2 (P1) — Настройка винта должна осуществляться через отдельный интерфейс с визуализацией битка.
  • ФТ-4.2.3 (P1) — Пользователь должен иметь возможность задать силу удара.
  • ФТ-4.2.4 (P1) — Сила удара задаётся в диапазоне от 1 до 4 с шагом 0.5.
  • ФТ-4.2.5 (P2) — Установленные параметры должны сохраняться и отображаться при повторном открытии позиции.

4.3. Линии и траектории

  • ФТ-4.3.1 (P1) — Пользователь должен иметь возможность добавлять линии типов: solid, dashed, solidWithArrow, dashedWithArrow.
  • ФТ-4.3.2 (P1) — Пользователь должен иметь возможность изменять начальную и конечную точки линии.
  • ФТ-4.3.3 (P2) — При перемещении шара привязанная линия должна корректировать своё положение.

4.4. Редактирование позиции

  • ФТ-4.4.1 (P1) — Пользователь должен иметь возможность сохранить позицию.
  • ФТ-4.4.2 (P1) — Пользователь должен иметь возможность открыть ранее сохранённую позицию.
  • ФТ-4.4.3 (P1) — Пользователь должен иметь возможность удалить любой элемент позиции.
  • ФТ-4.4.4 (P1) — Система должна запрашивать подтверждение при удалении позиции.

5. Назначение тренировок

5.1. Назначение упражнения

  • ФТ-5.1.1 (P1) — Тренер должен иметь возможность назначить упражнение спортсмену.
  • ФТ-5.1.2 (P1) — Назначение должно содержать дату выполнения.
  • ФТ-5.1.3 (P2) — Назначение может содержать период выполнения.
  • ФТ-5.1.4 (P2) — Система должна отображать список назначений по дате.

5.2. План тренировок

  • ФТ-5.2.1 (P2) — Спортсмен должен иметь возможность просматривать план тренировок на неделю.
  • ФТ-5.2.2 (P2) — Тренер должен иметь возможность просматривать план группы в календарном виде.

6. Ввод результатов

6.1. Фиксация результата

  • ФТ-6.1.1 (P1) — Спортсмен должен иметь возможность отметить попытку как успешную или неуспешную.
  • ФТ-6.1.2 (P1) — Результат должен сохраняться немедленно после ввода.
  • ФТ-6.1.3 (P2) — Для количественных упражнений должна быть возможность ввода числового результата.

6.2. История выполнения

  • ФТ-6.2.1 (P1) — Спортсмен должен иметь доступ к истории своих тренировок.
  • ФТ-6.2.2 (P1) — Тренер должен иметь доступ к истории тренировок спортсмена.
  • ФТ-6.2.3 (P2) — Должна быть реализована фильтрация по периоду и упражнению.

7. Аналитика

7.1. Индивидуальная аналитика

  • ФТ-7.1.1 (P1) — Система должна рассчитывать процент успешных попыток по каждому упражнению за выбранный период.
  • ФТ-7.1.2 (P1) — Система должна отображать динамику изменения процента успешных попыток в виде линейного графика.
  • ФТ-7.1.3 (P1) — Пользователь должен иметь возможность выбирать период отображения: день, неделя, месяц, произвольный диапазон.
  • ФТ-7.1.4 (P2) — Система должна рассчитывать средний результат по упражнению за выбранный период.
  • ФТ-7.1.5 (P2) — Система должна отображать лучший результат по упражнению за выбранный период.
  • ФТ-7.1.6 (P2) — Система должна рассчитывать стабильность выполнения (коэффициент вариации) и отображать её в виде числового значения или цветовой индикации.
  • ФТ-7.1.7 (P2) — Система должна поддерживать сравнение двух произвольных периодов с отображением разницы в процентах.
  • ФТ-7.1.8 (P2) — При сравнении периодов система должна отображать наложение графиков динамики для визуального анализа.
  • ФТ-7.1.9 (P3) — Система должна автоматически выявлять упражнения с отрицательной динамикой (снижение среднего результата более чем на 10% за период).
  • ФТ-7.1.10 (P3) — Система должна отображать текущий результат в процентах от личного рекорда спортсмена.
  • ФТ-7.1.11 (P3) — Система должна рассчитывать и отображать тепловую карту активности (количество тренировок по дням недели).

7.2. Групповая аналитика

  • ФТ-7.2.1 (P2) — Тренер должен иметь возможность просматривать средние результаты по группе для выбранного упражнения.
  • ФТ-7.2.2 (P2) — Система должна отображать положение каждого спортсмена относительно среднего по группе.
  • ФТ-7.2.3 (P2) — Тренер должен иметь возможность сравнивать до 5 спортсменов по одному упражнению на одном графике.
  • ФТ-7.2.4 (P2) — Система должна формировать рейтинг спортсменов внутри группы по выбранному упражнению.
  • ФТ-7.2.5 (P2) — Рейтинг должен рассчитываться на основе среднего процента успешных попыток за период.

7.3. Сводная аналитика по спортсмену

  • ФТ-7.3.1 (P2) — Система должна формировать сводную статистику по спортсмену за период:
  • Общее количество тренировок;
  • Общее количество выполненных подходов;
  • Средний процент успешных попыток по всем упражнениям;
  • Прогресс по сравнению с предыдущим периодом.
  • ФТ-7.3.2 (P2) — Система должна отображать список упражнений, по которым спортсмен показал наилучший и наихудший прогресс.- ФТ-7.3.3 (P3) — Система должна отображать динамику разряда/уровня спортсмена (при наличии ввода данных).

7.4. Алгоритмы расчёта

7.4.1. Процент успешных попыток

Рассчитывается как отношение количества успешных попыток к общему количеству попыток за период, выраженное в процентах.

7.4.2. Коэффициент вариации (стабильность)

Рассчитывается как отношение среднеквадратичного отклонения к среднему значению, выраженное в процентах. Чем ниже коэффициент, тем стабильнее результат.

7.4.3. Прогресс

Рассчитывается по формуле: ((Средний результат за текущий период - Средний результат за предыдущий период) / Средний результат за предыдущий период) * 100%.

7.4.4. Процент от рекорда

Рассчитывается как отношение текущего результата к лучшему за всю историю (или за период, по выбору пользователя), выраженное в процентах.

8. Комментарии

8.1. Комментарии тренера

  • ФТ-8.1.1 (P1) — Тренер должен иметь возможность оставить комментарий к тренировке.
  • ФТ-8.1.2 (P2) — Тренер должен иметь возможность оставить комментарий к отдельной попытке.
  • ФТ-8.1.3 (P2) — Комментарий должен сохраняться и быть доступным для повторного просмотра.

8.2. Заметки спортсмена

  • ФТ-8.2.1 (P2) — Спортсмен должен иметь возможность оставить заметку к тренировке.
  • ФТ-8.2.2 (P2) — Заметка спортсмена должна быть доступна тренеру.

9. Дополнительные функции

  • ФТ-9.1 (P2) — Спортсмен должен иметь возможность отметить своё состояние перед тренировкой (самочувствие, настроение) по 5-балльной шкале.
  • ФТ-9.2 (P3) — Система должна поддерживать экспорт статистики спортсмена в формате PDF или Excel.
  • ФТ-9.3 (P1) — Упражнение должно содержать наглядную схему позиции (визуализацию расстановки шаров).
  • ФТ-9.4 (P1) — Упражнение должно содержать текстовые рекомендации по выполнению.
  • ФТ-9.5 (P3) — Система должна отправлять push-уведомления о новых назначениях и напоминания о тренировках.
