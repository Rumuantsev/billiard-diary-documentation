# Документация бильярдного дневника

Репозиторий содержит проект документации для цифровой платформы «Электронный дневник бильярдиста». Документация собирается с помощью MkDocs и темы Material for MkDocs.

## Онлайн-версия

Актуальная опубликованная версия документации доступна по адресу:

```text
https://rumuantsev.github.io/billiard-diary-documentation/
```

Если онлайн-версия не обновилась после изменений, необходимо пересобрать и заново опубликовать сайт через используемый процесс деплоя документации.

## Локальный просмотр

Для локального просмотра перейдите в папку проекта документации:

```bash
cd billiard-diary-documentation
```

Запустите локальный сервер MkDocs:

```bash
mkdocs serve
```

После запуска документация будет доступна в браузере по адресу:

```text
http://127.0.0.1:8000
```

MkDocs автоматически обновляет страницу при изменении Markdown-файлов.

## Проверка и сборка

Обычная сборка:

```bash
mkdocs build
```

Строгая проверка перед публикацией:

```bash
mkdocs build --strict
```

Команда `mkdocs build --strict` должна выполняться без предупреждений. Если команда падает, чаще всего причина в битых ссылках, отсутствующих изображениях или страницах, которые не добавлены в `nav`.

## Основные файлы

- `mkdocs.yml` — главный конфигурационный файл: название сайта, тема, плагины, расширения Markdown и навигация.
- `docs/` — исходные страницы документации.
- `docs/openapi.yml` — OpenAPI-спецификация backend API.
- `docs/OpenAPI.md` — страница, на которой OpenAPI отображается через Swagger UI.
- `docs/diagrams/` — исходники диаграмм.
- `docs/out/` — готовые изображения диаграмм, которые подключаются в Markdown-страницах.
- `site/` — результат сборки. Эту папку не нужно редактировать вручную.

## Как добавлять и редактировать страницы

1. Создайте или измените Markdown-файл внутри `docs/`.
2. Добавьте страницу в раздел `nav` файла `mkdocs.yml`.
3. Проверьте локально через `mkdocs serve`.
4. Перед публикацией выполните `mkdocs build --strict`.

Пример добавления страницы:

```yaml
nav:
  - Новый раздел:
      - Новая страница: path/to/page.md
```

Путь в `nav` указывается относительно папки `docs`.

## Как работать с диаграммами

Исходники диаграмм хранятся в:

```text
docs/diagrams/
```

Готовые PNG-файлы хранятся в:

```text
docs/out/diagrams/
```

На страницах из папки `docs/Диаграммы/` изображения подключаются через путь с выходом на уровень выше:

```markdown
![Название](../out/diagrams/example/example.png)
```

Если страница находится прямо в `docs/`, путь будет другим:

```markdown
![Название](out/diagrams/example/example.png)
```

После добавления или замены изображения обязательно выполните:

```bash
mkdocs build --strict
```

## Как обновлять API-документацию

OpenAPI-спецификация находится в файле:

```text
docs/openapi.yml
```

После изменения API backend необходимо:

1. Обновить соответствующие пути, схемы и ответы в `docs/openapi.yml`.
2. Открыть локальную документацию через `mkdocs serve`.
3. Перейти на страницу `API`.
4. Проверить, что Swagger UI отображает обновленные endpoints.
5. Выполнить `mkdocs build --strict`.

## Правила поддержки документации

- Все текстовые правки вносятся только в файлы внутри `docs/`.
- Папку `site/` не редактировать вручную.
- Все страницы, которые должны быть видны в меню, необходимо добавлять в `nav` в `mkdocs.yml`.
- После перемещения Markdown-файла нужно обновить пути в `mkdocs.yml` и ссылки на изображения.
- После перемещения изображения нужно обновить Markdown-ссылки на него.
- Перед публикацией всегда запускать `mkdocs build --strict`.
- Если сборка падает, сначала проверить предупреждения MkDocs: они обычно прямо указывают на отсутствующий файл или неправильную ссылку.

## Частые проблемы

### Страница есть в папке `docs`, но не отображается в меню

Причина: страница не добавлена в `nav` файла `mkdocs.yml`.

Решение: добавить страницу в нужный раздел навигации.

### Картинка не отображается

Причина: неправильный относительный путь к изображению.

Решение: проверить, где находится Markdown-файл, и указать путь к картинке относительно этого файла.

### `mkdocs build --strict` падает

Причина: есть предупреждения сборки.

Решение: прочитать текст предупреждений. Обычно MkDocs показывает точный файл и неправильную ссылку.

### Онлайн-версия отличается от локальной

Причина: сайт не был пересобран или опубликован после изменений.

Решение: выполнить сборку и процесс публикации, который используется для данного репозитория.
